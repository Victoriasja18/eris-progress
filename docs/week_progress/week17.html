Comparison between the variant and collapse modes

def read_loci(report):
    """One row per IS name: its copies, from the number of loci (variant) or their copy_number (collapse)."""
    loci = pd.read_csv(report, sep="\t").drop_duplicates("locus_id")
    loci["copies"] = loci["copy_number"].fillna(1) if "copy_number" in loci else 1
    loci = loci.assign(target=loci["target"].str.split(",")).explode("target")  # a locus can hold several IS
    loci["name"] = loci["target"].map(mt.is_name)
    by_name = loci.groupby("name")["copies"].sum().reset_index()
    by_name["group"] = by_name["name"].map(mt.is_group)
    return by_name

IS–CDS relations by status and reason

Truth relations are TP or FN (wrong_side, wrong_IS, not_found); eris’s false nearest flanks are FP (unplaceable, wrong_side, wrong_IS, not_in_truth). Every FN also has a miss cause (budget, not_reported, not_called).

  • Variant mode reports every path through a collapsed repeat, not one consensus per repeat
  • Higher recall: a copy whose flanks collapse mode left out can still appear as a variant path. Every TP variant mode gains was a not_reported miss in collapse mode: 12 on simulated and 18 on real. They’re mostly multi-copy IS such as ISEc12 (4 and 5), IS26, ISEc23, IS200 and ISEc52.
  • Lower precision: the graph allows combinations that don’t exist in the genome. Each of those paths becomes a locus, and its nearest genes become FP calls. That’s why the extra FPs are almost all not_in_truth (29 → 44 on real) and come from multi-copy IS: ISEc8 (+3), IS30 (+3), ISEc23, ISEc12, IS1A and IS3411 (+2 each).
  • Precision counts each call: one extra path through a repeat adds two new nearest-flank calls, one per side. So every wrong path costs precision twice.

Comparing pyfgs and real FGS

  • I run FGS only in complete genome and found there are 5620 genes that are similar between pyfgs, genome

FragGeneScan 1.32 was run on the complete genome outside eris, with the complete model in both its modes: -w 0 (fragments, what eris uses: GeneFinder(model=Model.Complete, whole_genome=False)) and -w 1 (whole genome). Genes are compared by replicon, start, end and strand.

def read_genes(gff):
    genes = pd.read_csv(gff, sep="\t", comment="#", header=None, usecols=[0, 2, 3, 4, 6],
                        names=["replicon", "type", "start", "end", "strand"])
    genes = genes[genes["type"] == "CDS"]
    return set(genes[["replicon", "start", "end", "strand"]].itertuples(index=False, name=None))

New IS-CDS validation independent of gene quality

The curated score matches eris’s pyfgs genes to RefSeq CDS, so gene-calling errors (a spurious short ORF, a gene that misses the 50% overlap, a CDS pyfgs never called) count against eris. The new assignment score asks only: did eris attach its own genes to the right side of the right IS? The answer key is built from the truth IS BED and eris’s own called genes, and flanks are matched by gene ID, so gene calling cannot cause a mismatch.

Pipeline

  1. Run eris on each assembly twice: hops 3 is scored; hops 20 only tells a budget miss from not_reported.
  2. Place every gene eris called (CDS and pseudogenes in _assembly.gff) on the reference.
  3. Answer key: for each IS copy in the BED and each side (read along the BED strand), the nearest placed eris gene is expected. Tied genes, e.g. identical IS26 transposases, form one relation that any of them finds.
  4. Detected IS: the new _loci.fasta header gives each locus’s position (contig:start-end strand= or the contig path when stitched). A locus is placed with 1 kb of context to tell identical copies apart; a copy no locus covers is undetected.
  5. Score by gene ID: precision over eris’s nearest flanks (FP: unplaceable, overcall, wrong_side, wrong_IS, not_nearest_gene); recall over expected relations (FN: undetected, wrong_side, wrong_IS, not_found). The headline leaves the IS-detection errors (overcall, undetected) out.

any_copy vs own_copy

Every IS contains its own transposase, which is never its own flank. The two rules differ only for a gene inside a neighbouring IS: any_copy leaves out genes inside any IS copy, own_copy only those inside the copy being judged. eris itself walks outward and reports every gene it meets, so at two adjacent IS it reports the neighbour’s transposase.

  • This pattern (IS30/IS600, ISEc9/IS5, IS26/ISEcp1) is the whole difference on the complete genome: 16 FP under any_copy, 11 under own_copy.
  • Which rule is right is a biology question: should a neighbouring IS’s transposase count as “the gene next to this IS”? Decide by reading these rows, not by the higher score.
