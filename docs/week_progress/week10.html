Testing minimap2 parameters

There are 2 steps that I want to investigate:

  • Cross-file comparison (Same reference, same baseline params, different query fasta)

    • Complete genome fasta file
    • The locus assembly (for the complete genome, assembly graph)
    • Only using the ground truth fasta file

  • Per-file parameter tests

    • For EACH query fasta separately, run several mapping-time parameter varuants and compare them against each other

Everything can be seen in validate_minimap2.py and run_grid.sh

# ./run_grid.sh ../../data/IS.mmi ../result/mmi_compare \
#       complete_genome=../../data/EC958_complete_genome.fasta \
#       locus_assembly=../result/new_pipeline_gfa/new_pipeline_gfa_loci.fasta \
#       ground_truth=../../data/gt_IS_nc_new.fasta

Parameters:

  • Baseline: default
  • no_secondary:–secondary=no -> secondary alignment turned off
  • high_N: -N 20 -> controls how many secondary alignment is allowed to report per query
  • relaxed scoring: -A2 -B4 -O4,24 -E2,1, overrides minimap2 alignment scoring, to be more tolerant with indels or be stricter around mistmatches.

Grill me session

  1. OVERLAPPING_END (ISCfr4, IS4, ISEc22): _core_relate returns 6 when s_b >= s_a AND e_b > e_a — the pyfgs-called gene starts inside the IS locus but its end reaches past the locus boundary. Root cause: the locus boundary t_end is slightly shorter than the true IS end due to alignment soft-clipping, so genes near the IS 3′ boundary extend past the truncated locus.

To fix this we do CIGAR-aware boundary recovery: After the alignment, read the CIGAR soft-clipped bases and extend t_start/t_end by exactly those bases. Precise, only extends where the aligner actually soft-clipped

  1. IS26 FP (detected at 113K, ground truth at 30K): With 7 IS26 copies, eris can correctly produce 7 hits — but the copy at 30K may have enough sequence divergence from the ISfinder reference that mappy assigns it a low score, and cull_overlaps (or mappy’s own soft-clipping) produces a locus at the wrong position entirely.

alignment.py Fix 2: from_mappy() now accepts min_identity=0.75. Replaces if h.is_primary with if h.mlen / max(1, h.blen) >= min_identity — lets secondary alignments (e.g. ISSd1 next to IS30) survive; cull_overlaps handles deduplication Fix 1: New extend_is_bounds() method — after swap_sides(), q_start/q_length tell us how many IS reference bases are unaligned at each flank; extends the contig locus boundaries by those amounts so genes at the IS terminus are classified INSIDE not OVERLAPPING_END Bonus: Fixed pre-existing cull_overlaps bug where overlap fraction was divided by the candidate’s own length; now divides by the shorter of the two intervals (what the failing test test_asymmetric_overlap_bug was testing)

pipeline.py Fix 2: Pipeline.__init__ / slots now carry min_identity; _process_contig chains .extend_is_bounds() and passes min_identity to from_mappy()

cli.py Fix 3: Both Pipeline and LinearPipeline kwargs now include min_coverage and min_identity Fix 4: New –reference / -r flag; new –min-identity flag; calls build_contig_liftover() if GFA + reference given; passes liftover to OutputManager

io.py Fix 4: ReportRow gains optional ref_contig, ref_start, ref_end fields (default “.”); header(with_ref=) and to_tsv(with_ref=) control whether those columns appear; build_contig_liftover() aligns contigs to reference with asm5 preset; OutputManager accepts liftover dict and does linear interpolation per locus

import matrix as mt

def change_name(df):
  df["name"] = df["name"].astype(str) + "_" + df["repeats"].astype(str)
  df = df[["transcript", "chromStart", "chromEnd", "name", "repeats", "context"]]
  return df

fa_inside = change_name(fa_inside)
fa_overend = change_name(fa_overend)
fa_ups = change_name(fa_ups)
